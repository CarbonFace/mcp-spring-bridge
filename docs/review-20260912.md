# 2026-09-12 独立审查与处理记录

审查对象：Cogistra MCP Spring Bridge 初版。以下是本轮实现中实际发现并处理的缺陷，不是已发布版本的漏洞公告。完整运行证据在 [verification.md](verification.md)，对外版本仍为未发布 SNAPSHOT。

| 发现的问题 | 处理方式 | 验证入口 |
|---|---|---|
| 特殊 MVC 身份注入可能变成模型可提交的用户 DTO | 拒绝未实现的可信注入；Authentication/Principal 只从服务器上下文注入 | `UnsafeInjectionRegistrationTest` |
| 异步 Controller 可能在业务完成前记录成功 | 启动拒绝 Future/CompletionStage/DeferredResult/StreamingResponseBody 等不支持的返回 | 注册边界检查；不声称支持异步 |
| 准备时名称解析为 A，确认后动态映射为 B | 保存原始和已解析执行参数共同计算 hash；变化要求重新确认，执行已存绑定 | `ServletMcpIntegrationTest` 别名变化场景 |
| 数值节点 Integer/Long/BigInteger 表示差异导致误判变更 | 按数值语义比较绑定结果，持久化保持大整数/十进制 | 映射稳定后重新准备执行、core 持久化精度场景 |
| 成功回执重放或状态查询漏掉最新方法权限 | 对保存的实际参数重查当前身份、作用域、方法及宿主权限 | 撤销/账号隔离/重复提交场景 |
| 局部安全链导致 Boot 原默认私有页面失去保护 | 仅在宿主无自己安全链时保留受保护后备链 | `StarterDefaultSecurityIntegrationTest` |
| 业务 snake_case 或 Fastjson 影响 MCP 协议字段与序列化 | 独立协议 mapper 和 RouterFunctionMapping；业务 DTO 仍遵守自身 mapper | `ProtocolNamingIntegrationTest` |
| SDK JSON Schema 引擎版本冲突导致实际启动失败 | 统一 networknt 2.0.0，使用新版输入引擎及安全输出验证器 | 真实应用启动、正反 Schema 验证、依赖树 |
| 稀疏变更中的 Map 值 null 被错误拒绝 | 允许引用值 null，保留字段缺失与清空差异；实际 Bean Validation 仍生效 | 真实 HTTP/MCP 稀疏编辑场景 |
| 原生回调和文件导出可能漏掉公共控制 | 统一登记/执行；二进制转产物后仍做输出适配，原生错误按失败审计 | NativeAuthorizationTest、上传/导出与网络样例 |
| 重复文本/结构化预览挤占结果预算 | 框架结果只保留一份完整 structuredContent，文本给摘要，预览保存前保留回执空间 | 准备/状态/提交链路及静态预算检查 |
| 原生 URI/补全权限参数被外层错误重建 | 原生只读回调沿官方绑定器进入实际安全代理，公共层保留身份与额外策略 | 原生资源/模板/提示词/补全代理验证 |
| 共享存储中，本进程没有执行记录被误当成另一实例已崩溃 | 不用本进程状态猜测；存储或宿主负责权威恢复判定 | `OperationDurabilityTest` 双协调器共享存储场景 |
| 额外 HTTP header/params/正则路由条件可能在工具调用时丢失 | 首版明确拒绝未实现的映射条件与特殊路径，不静默降级 | 注册逻辑复审；普通路径、路径变量的实际请求场景 |
| 提交回调再次获取新身份，却仍用外层旧 SecurityContext 执行业务代理 | 在执行边界重新解析并安装当前业务 Authentication，finally 恢复外层上下文 | 实际提交链路与工作线程上下文成功/异常恢复场景 |
| Secured/JSR-250 权限改变后，旧回执路径只复查 PreAuthorize | 复用实际 Spring 前置授权拦截器重新判断全部支持守卫，保留宿主角色前缀与层级；不支持的过滤/后置守卫启动拒绝 | 实际 RPC 成功后撤销角色，status 与 submit 重放拒绝且不再次修改 |
| WRITE 策略错写派生工具名或重复资源名使配置失效/混用 | 全部注册完成后核对策略键，未知配置键和重复策略名启动拒绝；文档给出准确键表 | 完整应用启动拒绝错误 submit 键及重复资源策略键 |

文件归属与审计按 issuer、subject、clientId 隔离。默认 OAuth 授权使用签名令牌、PKCE、resource/audience、当前账号版本、刷新轮换及绝对授权期限。文件/操作/授权的持久化、并发与恢复分别有隔离回归。

未把本地测试写成实际桌面客户端、生产部署、生产业务事务或所有 Spring 版本的验收。发布前还需实际 GitHub CI、目标部署配置与宿主业务验收；客户端对话确认由客户端负责，服务器不能独立证明真人确认。磁盘突然断电、损坏介质或多实例共享存储需要对应部署验证。
